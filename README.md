# CS 255 DriverPass Portfolio
## Project Summary
The client was DriverPass, a company owned by Liam that wanted to help students pass their DMV driving test. Liam wanted a system where customers could take online practice tests, book in person driving lessons, and track their progress. Ian, the IT officer, needed the system to run in the cloud with secure logins and role based access for staff.
## What I Did Well
I did well breaking down the interview into clear functional and nonfunctional requirements. My diagrams, especially the class diagram, showed how customers, packages, reservations, and drivers connect so a developer could build from them without guessing.
## What I Would Revise
I would revise my class diagram by adding methods to each class, like bookLesson() and makePayment(). Right now it shows what the system stores but not what each part does. Adding methods would make it more complete for developers.
## Interpreting User Needs
I went back to the interview and pulled out exactly what Liam and Ian said they needed, such as scheduling lessons, tracking who made changes, and keeping data secure. I turned each need into a requirement and made sure it showed up in my diagrams. Considering user needs matters because a system can work perfectly and still fail if it doesn't solve the client's real problem.
## My Approach to Designing Software
I start by listening to the client and writing down requirements before thinking about code. Then I use UML diagrams to map out the users, the steps they take, and the data the system needs. In the future I would keep using interviews, use case diagrams, and activity diagrams, and I would check in with the client more often to confirm I'm on the right track.
